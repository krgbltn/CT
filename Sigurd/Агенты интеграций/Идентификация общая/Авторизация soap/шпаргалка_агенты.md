# Шпаргалка по общей идентификации через SOAP

## `identification.js`

Находит лицевые счета по телефону и помогает выбрать нужный по адресу.

| Параметр | Значение |
|---|---|
| Основной запрос | SOAP 1.1 `GetContractsInfo_By_Phone(PhoneNumber)` на `agentSettings.url` |
| Дополнительные запросы | GET `/{uid}/info`, GET `/{uid}/disconnection_report_info` |
| Вход | слот из `phoneSlotId`, по умолчанию `phone` |
| Технические входы | `classifier`, необязательный `next_article` |
| Успешные выходы | `uid`, `contract_no`, `address`, `status_ls`, `city`, `city_1`, `edds`, `house_type` |

### Логика

1. Один ЛС: спрашивает подтверждение адреса и записывает `id_step="confirm_single"`, `id_selected_index`, `id_contracts_data`.
2. Несколько ЛС: просит назвать адрес и записывает `id_step="ask_multiple"`, `id_contracts_data`.
3. Совпали населённый пункт, улица и основной номер дома одного уникального адреса → выбирает ЛС. Несколько разных полных совпадений → список.
4. Полного совпадения нет → считает совпавшие компоненты (населённый пункт, улица, дом). Единственного лучшего кандидата предлагает подтвердить (`confirm_partial`). «Да» → выбор, «нет» → список. Равные кандидаты либо отсутствие совпадений → список сразу.
5. В `choose_address` одним сообщением перечисляет уникальные адреса с номерами. Принимает число или словесный вариант («первый», «номер два», «третий адрес»). Допустимый номер → выбор без подтверждения, «нет» → оператор.
6. При выборе номера один раз переспрашивает с динамическим диапазоном `1…N`; повторная ошибка → оператор. При подтверждении один раз повторяет вопрос с адресом; повторная ошибка для вероятного адреса → список, для единственного ЛС → оператор.
7. После выбора заполняет данные исходного ЛС, определяет ЕДДС, получает статус, город и тип дома, переходит в следующую статью и сбрасывает служебное состояние.

Нормализация применяется с обеих сторон: адрес API и ответ клиента. Поддерживаются `дп`, цифровые и словесные числительные (`3-я` / «Третья», «семьдесят два» / `72`), регистр, пунктуация и `ё/е`. В названиях допускаются до 1 ошибки для слов длиной 5–6 символов и до 2 ошибок от 7 символов; короткие слова и числа сравниваются точно.

Одинаковые адреса объединяются, выбирается первый ЛС в порядке API. Литера, дробь, корпус, строение, квартира и тип улицы различают адреса. Номер дома `5` не совпадает с `15` или `50`; явно названные противоречащие детали исключают автоматический выбор полного совпадения.

**Повторные входы:** каждый вопрос возвращает все служебные слоты. Карта номеров хранится в `id_address_options` (индексы исходных контрактов); счётчики — `id_confirm_retry` и `id_number_retry`. При уточнениях API поиска не вызывается. Утрата/повреждение состояния → оператор. После завершения служебные слоты очищаются.

**Телефония:** на каждый вход ровно одно сообщение — вопрос, весь список либо команда перехода. Нетекстовые события → один `/ack`; повторный старт при активном шаге не расходует попытку.

**Ошибки:** ошибка запроса поиска, отказ от единственного ЛС, отказ от списка, исчерпание повторов или повреждение состояния → оператор. Корректный пустой результат SOAP и непредвиденная ошибка → `final_answer="error"` в следующую статью.

Поля SOAP: ID → uid, No → contract_no, Adress → address; City добавляется к адресу при отсутствии города. Ошибки HTTP/XML, SOAP Fault и неполные контракты → оператор. REST-токен и headers используются только для дополнительных запросов. Заглушка остаётся в прежнем формате общей идентификации.

## Сопоставление территорий SOAP

Справочники city1Values и eddsMapping в настройках не меняются. SOAP City сохраняется в WebProperties.City при передаче состояния между ходами. Город сравнивается целиком: Иркутск соответствует г Иркутск / город Иркутск, но не Иркутскому району. Учитываются регистр, пробелы, точки и ё/е. Название улицы не используется для определения территории.

Для city_1 сначала ищется точное название населённого пункта в city1Values. Если его нет, район ищется в полном адресе выбранного ЛС из account.house.address_object.full_address, запасное поле — account.house.address. Для edds используются город и район как разные территории. Статус, город и полный адрес извлекаются одним существующим запросом /info; отдельного запроса поиска по телефону REST нет.

Например, для SOAP City=Маркова район определяется только по полной карточке ЛС. Если карточка содержит р-н Иркутский, используются Иркутский из city1Values и соответствующая запись района из eddsMapping. Без сведений о районе он не угадывается. При ошибке /info сохраняется возможность сопоставления по SOAP City и Adress. При отсутствии совпадения city_1 и edds явно очищаются, чтобы не переносить результат предыдущего ЛС. Слот address сохраняет адрес SOAP, дополненный City.
