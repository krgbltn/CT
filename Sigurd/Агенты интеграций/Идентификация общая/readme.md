# Агент identification

Идентификация клиента по номеру телефона. Общий агент, используется во всех скриптах.

| Task | Entrypoint | Customer |
|---|---|---|
| Общая идентификация по телефону и адресу | `identification.js` | СИГУРД |

## Файлы

- `identification.js`
- `identification_settings.json`
- `identification.test.cjs` — локальные сценарные проверки без внешних зависимостей

## Метод API

REST GET /contracts_by_phone

## Входные данные

phone — номер телефона (из слота `phone`)

## Поля ответа

- UserId
- WebProperties.ContractNo
- WebProperties.Address
- WebProperties.GroupId
- IsRegistered

## JSONPath для slotsMapping

- uid = [0].UserId
- contract_no = [0].WebProperties.ContractNo
- address = [0].WebProperties.Address

## Заполняемые слоты

- uid — идентификатор лицевого счёта (UUID)
- contract_no — номер лицевого счёта
- address — полный адрес
- status_ls — статус ЛС из `GET /info.status`
- city — город из `GET /info.account.house.address_object.city`
- house_type — тип дома (OTHER/MKD/PRIVATE), из GET /disconnection_report_info
- city_1 — населённый пункт из `city1Values`, найденный в полном адресе выбранного ЛС
- edds — номер ЕДДС, определённый по территории из полного адреса выбранного ЛС
- id_step — состояние: `confirm_single`, `ask_multiple`, `confirm_partial`, `choose_address`
- id_selected_index — индекс предложенного на подтверждение контракта в исходном массиве API (с нуля)
- id_contracts_data — сериализованный список контрактов
- id_address_options — JSON-массив индексов исходных контрактов в порядке озвученных адресов; номер варианта = позиция в этом массиве + 1
- id_confirm_retry — число использованных повторов подтверждения (`0` или `1`)
- id_number_retry — число использованных повторов выбора номера (`0` или `1`)

## Дополнительные запросы

GET /{user_id}/disconnection_report_info — для получения house_type (тип дома)
GET /{user_id}/info — для получения city (город из account.house.address_object.city)

## Логика

### Первый вызов

1. Отправить GET /contracts_by_phone?phone={phone}
2. Если ответ пустой или не массив — вернуть `final_answer='error'` в `nextArticle`; дальнейшее действие определяется статьёй.
3. Если один лицевой счет:
   - Спросить: «Вы обращаетесь по адресу: {короткий адрес}? Скажите “да” или “нет”».
   - Установить `id_step=confirm_single`, `id_selected_index=0`, сохранить контракты и обнулить счётчики.
4. Если несколько лицевых счетов:
   - Спросить: "Назовите адрес, по которому Вы обращаетесь."
   - Установить `id_step=ask_multiple`, сохранить контракты и обнулить счётчики.

### Последующие вызовы (машина состояний)

#### confirm_single (один ЛС, ожидаем подтверждение)

- Положительный ответ (да/ага/верно и т.д.) → завершить идентификацию выбранным ЛС.
- Отрицательный ответ → перевод на оператора.
- Непонятный ответ → один раз повторить полный вопрос с адресом; повторный непонятный ответ → оператор.
- Противоречивый ответ «да нет» не считается подтверждением.

#### ask_multiple (несколько ЛС, ожидаем адрес)

1. Подготовить уникальные адреса. Для одинакового адреса использовать первый ЛС в порядке API. Литеры, дроби в номере дома, корпуса, строения, квартиры и тип улицы различают адреса.
2. Проверить полное совпадение населённого пункта, улицы и основного номера дома:
   - один подходящий уникальный адрес → завершить идентификацию;
   - несколько разных адресов → нумерованный список;
   - нет полного совпадения → частичное сопоставление.
3. Для частичного сопоставления посчитать независимо совпавшие компоненты: населённый пункт, улица, основной номер дома (по одному баллу):
   - единственный кандидат с наибольшим ненулевым результатом → `confirm_partial`;
   - нет совпадений либо несколько равнозначных лучших кандидатов → `choose_address`.

Нормализация применяется к адресу API и ответу клиента: регистр, `ё/е`, пунктуация, сокращения (включая `дп`), словесные числительные. `3-я`, `3 я`, «Третья», «третий» приводятся к одному значению; «семьдесят два» распознаётся как `72`.

В названиях допускаются замены, вставки и удаления букв: для слов до 4 символов — точное совпадение, 5–6 символов — до 1 ошибки, от 7 символов — до 2 ошибок (по более короткому слову). Числа сравниваются точно. Служебные слова «город», «улица», «дом» не являются совпавшими названиями.

Для номера дома сравнивается основная цифровая часть: `5` не равен `15` или `50`. Если клиент явно назвал литеру/дробь, корпус, строение или квартиру, противоречие этому значению исключает автоматический выбор полного совпадения. Если детали не названы и подходят несколько разных адресов, они остаются отдельными вариантами списка.

Поддерживаются краткие ответы без обозначений: `Марковой Медовая 5`. Слоты заполняются исходными значениями выбранного ЛС, а не нормализованным текстом.

#### confirm_partial (подтверждение вероятного адреса)

- Вопрос: «Вы обращаетесь по адресу: {короткий адрес}? Скажите “да” или “нет”».
- «Да» → завершить идентификацию.
- «Нет» → озвучить полный список уникальных адресов.
- Непонятный ответ → один раз повторить вопрос с адресом; повторный непонятный ответ → список.
- Последовательно подтверждать остальных кандидатов не требуется.

#### choose_address (выбор номера)

Список целиком передаётся в **одном сообщении**:

> Сейчас я перечислю найденные адреса, после этого назовите номер нужного адреса.
>
> Номер 1: Новое, Третья улица, дом 72.
>
> Номер 2: Иркутск, Трудовая, дом 129А, квартира 40.
>
> …
>
> Если нужного адреса нет в озвученном списке, ответьте словом «нет».

- Количество вариантов динамическое, одинаковый адрес озвучивается один раз.
- Короткий адрес содержит населённый пункт, улицу/микрорайон, дом, корпус/строение и квартиру. Если разобрать адрес для короткого представления нельзя, используется исходный адрес.
- Принимаются число и словесные формы: `1`, «один», «первый», «номер один», «второй адрес», «третий вариант», составные числительные до 999. Цифровая запись проверяется по фактическому диапазону списка.
- Допустимый номер → сразу завершить идентификацию, без дополнительного подтверждения.
- Только слово «нет» → оператор. «Ноль»/`0` не считаются отказом.
- Недопустимый или неоднозначный ответ («первый или второй», «нет второй») → один повтор: «Назовите номер адреса от 1 до {N} или скажите “нет”, если нужного адреса нет».
- Повторный некорректный ответ → оператор.

### Повторные входы и телефония

- Каждый вызов возвращает ровно один `ReplyMessage` в массиве `resolve([reply])`. Вопрос, список или команда перехода не сопровождаются вторым сообщением; `sendMessage` не используется.
- Каждый вопрос передаёт все служебные слоты следующего шага. Повторный вызов обрабатывается по `id_step` до запроса API; повторного поиска ЛС при уточнении нет.
- Индексы списка сохраняются в `id_address_options` и проверяются при выборе. Номер не трактуется как индекс исходного массива API напрямую.
- Повторный старт (`message_type=0`) при активном шаге повторяет текущий вопрос, не расходует попытку и не перезапускает поиск. Прочие нетекстовые события получают один `/ack` без изменения состояния.
- Повреждённые данные контрактов, неизвестный шаг, неверный индекс или утраченная карта вариантов → оператор.
- На успешном и неуспешном выходе служебные слоты сбрасываются; новый вход после завершения начинает новый поиск.

### Успешный выход

Все способы выбора вызывают общий обработчик: заполнить слоты из контракта, определить `city_1` и `edds`, получить `status_ls`, `house_type`, `city`, перейти в `nextArticle` (либо статью из слота `next_article`). Ошибка получения дополнительных сведений не отменяет выбор ЛС.

## Настройки (agentSettings)

- url — URL запроса с шаблоном {{slots.phone}}
- method — GET
- nextArticle — статья для продолжения сценария
- operatorArticle — статья для перевода на оператора
- city1Values — алфавитный список населённых пунктов для заполнения слота city_1; при совпадениях приоритетно самое длинное значение
- eddsMapping — соответствия вариантов территории из адреса и номера ЕДДС для заполнения слота edds
- slotsMapping — маппинг полей ответа на слоты
- disconnectionReportUrl — URL для получения house_type
- authorizationToken — Basic auth токен
- headers — HTTP заголовки
- stub / stubResponse — заглушка для тестирования

## Перевод на оператора

Диалог направляется через `classifier` в статью `operatorArticle`.

Срабатывает при:
- Ошибка запроса к API
- Отказ от единственного ЛС либо повторный непонятный ответ на его подтверждение
- Ответ «нет» на нумерованный список либо повторный некорректный выбор номера
- Нет корректных данных состояния при последующем вызове

Пустой/некорректный ответ поиска и непредвиденная ошибка выполнения возвращают `final_answer='error'` в `nextArticle`.

## Заглушка (stub)

В development-режиме агент может использовать stubResponse — массив из 6 тестовых контрактов. Включается параметром stub: true в настройках.

## Проверка

Из корня репозитория:

```powershell
node --check "Sigurd/Агенты интеграций/Идентификация общая/identification.js"
node --test "Sigurd/Агенты интеграций/Идентификация общая/identification.test.cjs"
```

Тесты запускают каждый ход в новом JS-контексте, переносят только слоты ответа, проверяют одно сообщение на вызов, отсутствие повторного поиска при уточнениях, переходы и ограничения повторов, нормализацию, дубли и размер скрипта (до 32 766 байт).
