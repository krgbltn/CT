# Начисления

JS-агенты получают данные по лицевому счету из REST API СИГУРД и передают результат в следующий сценарий.

| Task | Entrypoint | Customer |
|---|---|---|
| Сумма к оплате по услуге | `get_service_amount_to_pay.js` | СИГУРД |
| Общая задолженность | `get_total_debt.js` | СИГУРД |
| Проверка приборов учета воды | `check_water_devices.js` | СИГУРД |
| Задолженность по услуге | `check_service_debt.js` | СИГУРД |
| Проверка переплаты | `check_overpayment.js` | СИГУРД |
| Проверка доставки документов на email | `check_email_doc.js` | СИГУРД |

## Агенты

### get_service_amount_to_pay

Получает операции по ЛС `uid` (GET `/{uid}/transactions`), отбирает все строки, `service_name` которых содержит один из алиасов слота `service_type` (настройка `serviceNames`: `Электроснабжение`/`Электроэнергия`, `ХВС`/`Холодное водоснабжение`, `ГВС`/`Горячее водоснабжение`, `Отопление`), суммирует их `debt` и передает положительную сумму в `amount_to_pay` вместе со значением услуги в `service_name`. Если долг нулевой или отрицательный (переплата), передается `0`. Слот `final_answer`: `1` — `amount_to_pay > 0`, `2` — суммы нет. Неизвестный `service_type`, отсутствие совпадений или ошибка запроса — перевод на оператора.

### get_total_debt

Получает суммарное сальдо ЛС `uid` из `account.balance` (GET `/{uid}/info`) и передает его сырым в слот `balance`, положительную задолженность в `amount_to_pay` вместе с `final_answer`: `1` — долг есть, `2` — долга нет (ноль или переплата), `3` — `account.balance` отсутствует в ответе. Сырое значение `account.balance` пишется в лог до трактовки знака. При отсутствии `uid`, некорректном значении `balance` или ошибке запроса переводит диалог на оператора.

### check_water_devices

Проверяет наличие приборов учета ГВС и ХВС для ЛС `uid` по `account.devices` (`GET /{uid}/info`), сопоставляя `service_name` с алиасами из настройки `serviceNames` (`ГВС`/`Горячее водоснабжение`, `ХВС`/`Холодное водоснабжение`), дополнительно ГВС определяется по `is_hot_water`. Заполняет `final_answer`: `1`, если найден хотя бы один прибор (ГВС или ХВС) и хотя бы один из найденных принимает показания (`accepts_readings === true` либо `readings_accept_type === "allowed"`), иначе `2`. Статус услуги не определяется — в API отдельных услуг и их статусов нет.

### check_service_debt

Получает задолженность по услуге из слота `service_name`. Передает `service_name` и `amount_to_pay`; положительное значение задолженности используется как сумма к оплате.

### check_overpayment

Суммирует задолженности по всем услугам ЛС `uid`. При переплате передает абсолютное значение в `overpayment_amount` и `final_answer: "1"`; при ее отсутствии передает `final_answer: "2"`.

### check_email_doc

Проверяет параметры `email_doc` и `email` для ЛС `uid`. Передает `final_answer`: `1` для включенной доставки на адрес `.ru`, `2` для другого адреса, `3` для отключенной доставки.

## Маршрутизация

Все агенты получают ID ИИ-агента из слота `classifier`. Целевая статья берется из `next_article`; если слот не заполнен, используется `nextArticle` из настроек. При ошибке запроса или неполных обязательных данных диалог направляется в статью `operatorArticle`.
