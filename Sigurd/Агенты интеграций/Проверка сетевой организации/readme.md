# Проверка сетевой организации

| Task | Entrypoint | Customer |
|---|---|---|
| Проверка возможности подачи заявки и получение контактов сетевой организации | `check_network_organization.js` | Sigurd |

Агент получает сведения по выбранному ЛС и возвращает в сценарий код дальнейшего действия. Числа в `network_organization_id` больше не обозначают конкретную организацию.

## Запрос и настройки

GET `/{uid}/disconnection_report_info`. Вход: `uid` выбранного ЛС и `classifier`. Если по телефону найдено несколько ЛС, выбор адреса должен завершиться до вызова агента.

Настройки находятся в `check_network_organization_settings.json`:

- `url`, `method`, `headers`, `authorizationToken` — параметры GET-запроса; заголовок `Host` должен быть без порта.
- `nextArticle` — статья продолжения, если слот `next_article` не задан.
- `operatorArticle` — статья перевода на оператора при ошибке.

Авторизацию и коды статей задают для окружения при развёртывании. Старый `slotsMapping` для `Id` удалён: четыре выходных слота формируются логикой агента.

## Ветвление

Условия проверяются по порядку таблицы. Значения слотов передаются строками.

| Приоритет | Условие | `network_organization_id` | Действие сценария |
|---|---|---|---|
| 1 | `hasrequest === true` | `"4"` | Озвучить `{{request_text}}`, новую заявку не оформлять |
| 2 | В любом контакте `networkorganizationid` равен нулевому GUID | `"3"` | Перевести на оператора |
| 3 | `network_organization_data.request_allowed === true` | `"1"` | Перейти к заполнению заявки |
| 4 | `network_organization_data.request_allowed === false` | `"2"` | Озвучить сообщение и телефон сетевой организации |

Нулевой GUID: `00000000-0000-0000-0000-000000000000`. Такой случай логируется. Если заявка уже существует, её текст имеет приоритет даже при нулевом GUID.

Для ветки `"2"` выбирается первая запись `contact_type === "Phone"` с непустыми строками `message` и `contact`. Положение телефона в массиве не фиксировано. Telegram и Max голосом не озвучиваются. Название организации уже включено в `message`; отдельно извлекать его не требуется. Верхнеуровневый `request_allowed` не используется: источник решения — вложенное поле в `network_organization_data`.

## Слоты

| Слот | Тип | Источник / назначение |
|---|---|---|
| `network_organization_id` | Строка, существующий слот | Код действия `"1"`, `"2"`, `"3"` или `"4"` |
| `network_organization_message` | Строка, новый слот | `message` выбранного телефонного контакта для ветки `"2"` |
| `network_organization_phone` | Строка, новый слот | `contact` того же контакта для ветки `"2"` |
| `request_text` | Строка, новый слот | `requesttext` для ветки `"4"` |

Агент каждый раз явно передаёт все четыре слота; неиспользуемые значения равны пустой строке. При ошибке все четыре очищаются в ответе перевода на оператора.

Текст для ветки `"2"`:

```text
{{network_organization_message}} по телефону {{network_organization_phone}}
```

Текст для ветки `"4"`:

```text
{{request_text}}
```

## Ошибки

При отсутствии `uid`, ошибке запроса, некорректном ответе или не булевом `hasrequest` агент возвращает перевод через `classifier` в `operatorArticle`. Для существующей заявки обязателен непустой `requesttext`. После проверки нулевого GUID требуется булевое вложенное `request_allowed`; в ветке `"2"` обязательны телефон и сообщение. Ошибки не подменяются кодом `"1"`.

Все четыре штатных результата возвращаются в `next_article` / `nextArticle`, включая `"3"`: перевод по этому коду нужно настроить в сценарии. Агент не создаёт заявку и не заполняет `final_answer`.

## Изменения на платформе

1. Создать три новых строковых слота из таблицы выше. Сохранить существующие `uid`, `classifier`, `next_article` и `network_organization_id`.
2. Загрузить обновлённый JS и настройки агента. Сохранить авторизацию и статьи своего окружения. Удалить старый `slotsMapping`, проверить `url`, `method: "get"` и `Host` без порта. Задать `nextArticle` либо передавать `next_article` — статья продолжения должна содержать новое ветвление.
3. Заменить старые проверки организаций `1/2/3/4` четырьмя ветками из таблицы. Обновить также другие сценарии, использующие этот агент: значения больше не означают ИЭСК/БЭСК/ОКЭ/другое.
4. В ветке `"2"` озвучивать сообщение и телефон; в `"4"` — только текст существующей заявки. Из веток `"2"`, `"3"`, `"4"` не должно быть перехода к подаче новой заявки.
5. Проверить четыре исхода и ошибку API на тестовых данных платформы; при смене ЛС проверить отсутствие старых текстов и контактов.

Подача заявки выполняется отдельным агентом `ksrt_report`: он отправляет один POST без повторного GET. Формат тела и обработка успешного пустого ответа исправлены; см. документацию в папке «Отключение ЭЭ».

## Локальная проверка

Из корня репозитория, без установки зависимостей:

```powershell
node --test 'Sigurd/Агенты интеграций/Проверка сетевой организации/tests/check_network_organization.test.cjs'
```

Тесты запускают агент в изолированном контексте с моками всех глобальных объектов и HTTP. Боевые сервисы не вызываются.
