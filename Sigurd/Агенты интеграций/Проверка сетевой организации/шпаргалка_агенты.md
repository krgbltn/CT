# Шпаргалка по проверке сетевой организации

## `check_network_organization.js`

Получает разрешение на заявку, существующую заявку и контакты для выбранного ЛС.

| Параметр | Значение |
|---|---|
| Запрос | GET `/{uid}/disconnection_report_info` |
| Вход | `uid`, `classifier`; `next_article` переопределяет статью продолжения |
| Выход | `network_organization_id`, `network_organization_message`, `network_organization_phone`, `request_text` |
| Заголовок | `Host` без порта, задаётся в настройках |

Приоритет проверки:

1. `hasrequest === true` → `network_organization_id="4"`, `request_text` из `requesttext`; озвучить, новую заявку не подавать.
2. Нулевой GUID в любом контакте → `network_organization_id="3"`; перевод на оператора настраивается в сценарии.
3. Вложенный `network_organization_data.request_allowed === true` → `network_organization_id="1"`; заполнение заявки.
4. Вложенный `request_allowed === false` → `network_organization_id="2"`; сообщение и телефон из первой полной записи `Phone`.

Текст ветки `"2"`: `{{network_organization_message}} по телефону {{network_organization_phone}}`.

Текст ветки `"4"`: `{{request_text}}`.

Дополнительно создать три строковых слота: `network_organization_message`, `network_organization_phone`, `request_text`. Все выходные слоты передаются при каждом вызове, неиспользуемые очищаются. `final_answer` не заполняется.

При ошибке API, отсутствии `uid`, некорректном ответе или отсутствии обязательного текста/телефона — перевод через `operatorArticle` с очисткой выходных слотов. Штатные четыре результата возвращаются в `next_article` / `nextArticle`.

Числа `1/2/3/4` больше не обозначают названия организаций. Агент подачи заявки не изменён.
