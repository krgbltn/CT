# Шпаргалка по агентам приборов учета

## Общие слоты

Все агенты после идентификации используют:

- `uid` — ID выбранного лицевого счёта.
- `classifier` — ИИ-агент для возврата.
- `next_article` — необязательная статья продолжения.

При технической ошибке агенты переводят диалог в `operatorArticle`.

## Агенты

| Агент | Что делает | Входные слоты | Результат и логика |
|---|---|---|---|
| `check_service_device.js` | Проверяет услугу на ЛС и приборы по этой услуге | `uid`, `service_type` | `/info`: ищет услугу в `account.accounts[].services[]`, приборы в `account.devices[]`. Возвращает `service_exists`, `service_active`, `device_exists`, `device_active` как `"true"`/`"false"`, также при наличии: `service_name`, `readings_accept_type`, `city`, `house_type`. `device_active="true"`, если у любого прибора `accepts_readings=true`. |
| `check_device.js` | Проверяет конкретный электросчётчик | `uid`, `device` = ID прибора | `/info`: ищет прибор с таким `id` и `service_name`, содержащим `Электроснабжение`. Если найден: `final_answer="1"`, возвращает `device`, `service_name`, `city`, `house_type`, `readings_accept_type`. Если нет: `final_answer="2"`. |
| `check_housetype.js` | Получает тип дома | `uid` | `/disconnection_report_info`: возвращает `housetype` и `final_answer="1"`, если тип найден; иначе `"2"`. |
| `device_verification_check.js` | Получает дату следующей поверки первого прибора выбранной услуги | `uid`, `service_type` | `/info`: ищет первый прибор услуги в `account.devices[]`. Если у него есть `next_check`: возвращает `next_check`, `final_answer="1"`. Если прибора или даты нет: `final_answer="2"`. Дату с текущим днём не сравнивает. |
| `last_reading_get.js` | Получает последнее показание одного прибора услуги | `uid`, `service_type` | `/devices`: берёт первый прибор, где `service_name.includes(service_type)`, и первое показание. Возвращает `device` (ID), `last_reading`, `last_reading_date`. Если прибора или показаний нет, переводит к оператору. |
| `get_all_last_readings.js` | Получает последние показания по всем приборам ЛС | `uid` | `/devices`: берёт первое показание каждого прибора. Возвращает `readings_text`, `devices_readings` (JSON) и `final_answer`: `"1"` есть показания, `"2"` приборов нет, `"3"` приборы есть, показаний нет. |

## Значения `service_type`

Для `check_service_device.js` и `device_verification_check.js` сценарий должен передавать строго одно из значений:

- `Электроэнергия`
- `Холодное водоснабжение`
- `Горячее водоснабжение`
- `Отопление`

Внутри агенты учитывают алиасы API: `Электроснабжение`/`Электроэнергия`, `ХВС`/`Холодное водоснабжение`, `ГВС`/`Горячее водоснабжение`.

## Выбор агента

- `check_service_device.js` — услуга есть на ЛС, есть ли прибор и доступен ли приём показаний.
- `device_verification_check.js` — дата следующей поверки прибора выбранной услуги.
- `get_all_last_readings.js` — последние показания всех приборов ЛС без уточнения услуги.

`get_all_last_readings.js` возвращает перечисление в `readings_text`. Вопрос «Вы передавали эти показания?» сценарий добавляет самостоятельно.
