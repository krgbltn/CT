# Приборы учета

JS-агенты получают сведения о приборах учета и типе дома из REST API СИГУРД. Агенты приема и передачи показаний описаны отдельно в `Прием показаний/readme.md`.

| Task | Entrypoint | Customer |
|---|---|---|
| Проверка электросчетчика | `check_device.js` | СИГУРД |
| Проверка типа дома | `check_housetype.js` | СИГУРД |
| Проверка даты поверки | `device_verification_check.js` | СИГУРД |
| Получение последнего показания | `last_reading_get.js` | СИГУРД |

## Агенты

### check_device

Проверяет наличие выбранного слотом `device` прибора электроснабжения для ЛС `user_id_tst`. При успехе передает сведения о приборе: `device`, `service_name`, `city`, `house_type`, `readings_accept_type` и `final_answer: "1"`. Если прибор не найден, передает `final_answer: "2"`.

### check_housetype

Получает тип дома для ЛС `user_id_tst`. Передает значение в `housetype` и `final_answer`: `1`, если тип определен, иначе `2`.

### device_verification_check

Проверяет дату следующей поверки прибора из слота `device`. Передает `device`, `next_check` и `final_answer`: `1`, если поверка еще не наступила, `2`, если срок наступил, `3`, если прибор или дата не найдены.

### last_reading_get

Находит прибор для услуги из слота `service_type` и передает `device`, `last_reading` и `last_reading_date`.

## Маршрутизация

Все агенты получают ID ИИ-агента из слота `classifier`. Целевая статья берется из `next_article`; если слот не заполнен, используется `nextArticle` из настроек. При ошибке запроса или неполных обязательных данных диалог направляется в статью `operatorArticle`.
