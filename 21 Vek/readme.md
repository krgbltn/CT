# Ассистент оператора 21 век

| Task | Entrypoint | Customer |
|---|---|---|
| Помощь оператору контакт-центра | `gpt_assistant_agent_21vek.js` | 21 век |

Ассистент скопирован с `../Skolkovo/gpt_assistant_agent_skolkovo.js`.
Он возвращает подсказки в рабочее место оператора; сам не отправляет сообщения
клиенту, не оформляет заказы и не переводит диалог между агентами.
Диалоговый бот с тулзами описан отдельно в [tools/readme.md](tools/readme.md).

## Сохранённые функции

Меню `get_request_types` и идентификаторы команд совпадают с исходником.

| Команда | Функция |
|---|---|
| `gpt_answer` | Ответ на вопрос клиента по найденному контексту |
| `detailed` | Более подробный ответ по тому же механизму |
| `reject` | Исправление орфографии, пунктуации и грамматики |
| `fix_syntax` | Улучшение ясности и вежливости ответа оператора |
| `summary` | Краткое изложение запроса по сообщениям клиента |
| `trans_en` | Перевод на английский |
| `empathy` | Рекомендации по ведению диалога и признак `alarm` |
| `tone` | Тональность и рекомендация оператору |
| `adaptation` | Адаптация черновика под манеру общения клиента |
| `crm` | Поиск настроенной карточки клиента |

Как в исходнике, также поддерживаются команды, не включённые в меню:
`trans_chinese`, `trans_uz`, `trans_kg`, `trans_ru`, `trans_tj`, `sell`.
Флаг `nonActiveDialog: true` при обычном запросе запускает сводку предыдущего
диалога и предложение сообщения для возобновления общения.

Перевод использует черновик `operatorMessage`, а при его отсутствии — первое
сообщение клиента из переданного массива. Подсказка по базе использует то же
первое сообщение клиента и черновик оператора, как в исходнике. Передавайте
выбранное актуальное сообщение клиента первым.

## Правила проекта

Промпты адаптированы под контакт-центр онлайн-гипермаркета «21 век»:
оформление и изменение заказа, товары, оплата, доставка, получение, возврат,
гарантия и другие услуги в пределах найденной информации.

Ответы по базе строятся только по релевантному контексту. По умолчанию
используются розничные условия; оптовые допустимы при явном упоминании опта.
Нельзя выдумывать цены, наличие, ставки, сроки, телефоны, статус заказа или
результат действий. При нехватке информации формируется честная фраза о
необходимости уточнения; личные обращения допускают краткий дружелюбный ответ.

Редактирование, адаптация, продажа, сводка и переводы сохраняют факты входного
текста. Рекомендации по диалогу относятся к поддержке клиентов магазина;
скрипт Академии наставников и промпт Белпочты не используются.

## CRM

В исходнике `crm` возвращала жёстко заданную демонстрационную карточку.
Настоящего обращения к CRM в ней не было. Для демонстрации 21 век в
`crm_clients` добавлена тестовая карточка. Массив содержит объекты с полями
`phone`, `card` и необязательным `demo`. При `demo: true` карточка явно
помечается как демонстрационная.

Для показа напишите в диалоге тестовый номер **0000000000** и выберите
«Обратиться к CRM». Ассистент покажет карточку демонстрационного клиента,
товар и заказ `DEMO-001`. При другом номере возвращается «Клиент не найден».
При пустом массиве — «Источник данных CRM не настроен».
Для реальной CRM потребуется отдельно согласованный API-контракт и интеграция.

## Подключение и настройки

Создайте отдельного JS-агента из `gpt_assistant_agent_21vek.js`, загрузите
`gpt_assistant_agent_21vek_settings.json` и подключите его как ассистента
рабочего места по принятой в проекте конфигурации. Модули не требуются.

Контракт соответствует исходному ассистенту: входной JSON имеет `mode`,
`reqTypeCommand`, `operatorMessage`, массив `messages` с полями `side`/`text`
и необязательный `nonActiveDialog`. Поддерживается также JSON в Buffer.
`mode: "get_request_types"` возвращает меню, `mode: "gpt"` — подсказку.
Это JSON-контракт рабочего места, а не обычный диалоговый `ReplyMessage[]`.

| Настройка | Назначение |
|---|---|
| `customer_id`, `record_type` | Клиент и тип записей поиска; перенесены из настроек GPT проекта |
| `base_url` | Полный URL платформы для ссылок на статьи |
| `url_context_search`, `url_llm` | Сервисы поиска и craftgpt |
| `llm_auth_token` | Ключ craftgpt; должен быть действующим, активным и не просроченным |
| `llm_timeout`, `llm_temperature` | Таймаут в секундах и температура генерации |
| `isThinking` | Суффикс thinking модели; блоки `<think>` удаляются из подсказок |
| `isSupport` | Возвращать ссылки на найденные статьи оператору |
| `llm_system_template` | Основной промпт ответа по базе |
| `llm_system_template_smalltalk` | Промпт при отсутствии контекста |
| `crm_clients` | Локальные карточки; включена тестовая карточка для демонстрации CRM |

Адреса, ключ и фильтр поиска скопированы из настроек проекта. Их значения
в документации не приводятся. Настройки имеют плоскую структуру, как
у исходного ассистента Skolkovo, а не вложенную структуру диалогового бота.

## Результат и ошибки

Подсказка возвращается через `resolve({alarm, message, supportArticles})`.
Ссылки на статьи имеют поля `ref` и `title`; повторяющиеся статьи исключаются.
При ошибке, которую не обработала команда, возвращается `{error: "…"}`
с нейтральным сообщением без содержимого HTTP-запроса и ключа.
Пустой ввод для редактирования или перевода возвращает подсказку оператору.
Неподдерживаемый режим и некорректный JSON также завершаются через `resolve`.

В журнал записываются название команды, режим, количество найденных фрагментов
и диагностические сведения об ошибках. Полные диалоги, карточки и токен
в новые журнальные записи не выводятся.

## Проверка

Из корня репозитория:

```powershell
node --check '21 Vek/gpt_assistant_agent_21vek.js'
node --test '21 Vek/gpt_assistant_agent_21vek.test.cjs'
```

Тесты выполняются в VM с подменённым axios, без внешних запросов. Проверяются
совпадение меню с исходником, все команды, контекст и ссылки, CRM, пустой ввод,
Buffer и ошибки. Качество генерации и подключение рабочего места нужно
проверить в тестовом окружении с действующим ключом craftgpt.
