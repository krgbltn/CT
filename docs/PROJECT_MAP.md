## Общая организация

Это коллекция агентов и инструментов. Клиентские папки не являются пакетами
единого приложения: общего `package.json`, сервера и общей сборки в корне нет.
Большинство JavaScript-файлов предназначены для среды CraftTalk, а не для
самостоятельного запуска через Node.js.

### Модульный GPT

Базовый путь: `Craft/jsagent-scripts-main-scripts-gpt/scripts-gpt/gpt-modular/`.

```text
gpt-modular/
├── modules/
│   ├── core/           # 10_globals.js … 80_main.js, включая 55_slots.js и 65_mcp.js
│   └── models/         # qwen.js, qwen_yandex.js, gigachat.js, default.js
├── client_scripts/     # gpt_tools, gpt_ida_qwen, gpt_rupost, gpt_bank_soyuz и настройки
├── __tests__/          # core/, models/, helpers/, e2e/
├── build.sh            # Конкатенация modules/core/[0-9]*.js в порядке имён
├── gpt_core.js         # Результат сборки
├── package.json        # Команды Vitest
├── vitest.config.js    # Локальные проверки без e2e
└── vitest.e2e.config.js # Проверки с внешними сервисами
```

В платформе код подключается в порядке: core → модель → клиентский скрипт.
Это общая область выполнения, а не обычные импорты npm-пакетов.
Клиентские скрипты задают промпты, инструменты и `_main()`, применяют
`applyPromptOverrides()`, `applyModelConfig()` и вызывают `runEntrypoint()`.
Подробности — в [README модуля](../Craft/jsagent-scripts-main-scripts-gpt/scripts-gpt/gpt-modular/README.md).

Копии `gpt_core.js` встречаются в `Brainstorm/gpt_tools/`,
`Craft/GPT Qwen/GPT TOOLS/`, `Едоставка/gpt edostavka/`, `тест/Прочее/`.
Совпадение имён не гарантирует совпадения версий. Общую логику изменяйте в
`modules/core/`, затем собирайте; необходимость обновить конкретную клиентскую
копию определяется задачей.

| Путь относительно `Sigurd/` | Назначение |
|---|---|

| `Шаблоны агентов запросов/` | `rest.js`, `soap.js`, настройки и отдельные инструкции [REST](../Sigurd/Шаблоны%20агентов%20запросов/rest_README.md) / [SOAP](../Sigurd/Шаблоны%20агентов%20запросов/soap_README.md) |
| `Агенты интеграций/` | Реализации; [all_agents.md](../Sigurd/Агенты%20интеграций/all_agents.md), локальные README и шпаргалки |

| `PROD_settings_checklist.md` | [Список настроек для переноса](../Sigurd/PROD_settings_checklist.md); значения проверять для конкретного окружения |

Категории в `Агенты интеграций/`: `Идентификация общая/`, `Договорная работа/`,
`Дистанционные сервисы/`, `Начисления/`, `Отключение ЭЭ/`, `Отключения ТСН/`,
`Проверка сетевой организации/`, `Приборы учета/`, `Юридические лица/`.
В `Приборы учета/Прием показаний/` находятся отдельные агенты идентификации
и `submit-readings.js`.

Обычно рядом лежат `<имя>.js`, `<имя>_settings.json` и README. Частые элементы
контракта: входные слоты, шаблоны HTTP-запроса, `slotsMapping`, статья продолжения
и переход при ошибке. Точные имена и значения нужно читать у выбранного агента:
шаблон и клиентская реализация могут различаться.

## Вспомогательные и служебные файлы

`Истории диалога/src/HistoryMessagesRender.py` связывает API-клиент
`src/API/CrafttalkAPI.py` с рендерами `src/ElementRender/`. Проверки рендеров
используют `unittest`. Notebook может обращаться к API, поэтому его выполнение
не является обычной проверкой исходников.

Утилиты `Готовые скрипты/` используют локальные исходные файлы; в части кода
есть привязки к диску `D:`. Перед запуском проверяйте пути и ожидаемые результаты.

`.idea/` — настройки IDE; `.opencode/` и `opencode.json` — конфигурация инструмента
разработки. Их зависимости не являются зависимостями агентов CraftTalk.
Корневые `tst.js`, `tst.json` не объявлены общей точкой входа.
Папки `back/`, `backup/` и файлы с суффиксами `_back`, `_old` требуют проверки
актуальности перед использованием как образца.

## Особенности текущей копии

- Указанный в прежних инструкциях `scripts/.Example-1/` отсутствует. Используйте
  подходящего соседа или шаблоны Sigurd, сохраняя местные соглашения.
- В README модульного GPT упомянут `.githooks`, но такого каталога в этой копии
  не обнаружено. Сборку следует выполнять явно, не полагаясь на хук.
- В старых README встречаются команды установки зависимостей. Для работы
  помощника действует запрет установки из корневого `AGENTS.md`.
- README импорта называет `--limit 2` сухим прогоном. По коду это ограничение
  числа строк: запросы создания и публикации всё равно выполняются.

Команды проверки и порядок изменений — в [WORKFLOW.md](WORKFLOW.md).
